# project-architecture-map integration

The inspection panel is rendered inside the HTML generated by `project-architecture-map`. The map manifest declares profiles and resource bindings; Resource Inspector serves that exact HTML and handles the local inspection requests. No separate dashboard is involved.

## Manifest contract

Declare the profile options and map each clickable node to resource IDs:

```json
{
  "resourceProfiles": [
    { "id": "local", "name": "Local", "kind": "local" },
    { "id": "cloud", "name": "Cloud", "kind": "cloud" }
  ],
  "tabs": [
    {
      "diagrams": [
        {
          "nodes": [
            {
              "id": "api",
              "resourceRefsByProfile": {
                "local": ["api-process", "api-container", "api-logs", "api-requests"],
                "cloud": ["api-health-cloud", "api-logs-cloud", "api-requests-cloud"]
              }
            }
          ]
        }
      ]
    }
  ]
}
```

The updated `project-architecture-map` generator validates profile IDs and resource bindings, renders keyboard-accessible node buttons, and embeds the localized inspector panel. Check that the installed generator includes this integration before promising clickable nodes; if it does not, update its manifest validator and HTML template as part of the setup. A node can bind several resources so its status, logs, and request history appear together. Keep the binding list scoped to each node and profile.

Build the MCP repository, then run the generated map through `pnpm --dir <resource-inspector-repo> map --map ...`. A directly opened `file://` map stays static because browser requests cannot reach the local MCP viewer.

The sample cloud profile monitors HTTP health endpoints, database, queue, and log store. It does not include a cloud container control-plane integration. Configure a remote Docker context or add a provider connector for Kubernetes or managed container platforms.
