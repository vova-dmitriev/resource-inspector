# project-architecture-map integration

The inspection panel is rendered inside the HTML generated by `project-architecture-map`. The map manifest declares profiles and resource bindings; Resource Inspector serves that exact HTML and handles local inspection requests. No separate dashboard is involved.

Declare available profiles and bind each clickable node to the resource IDs that represent it:

```json
{
  "resourceProfiles": [
    { "id": "local", "name": "Local", "kind": "local" },
    { "id": "cloud", "name": "Cloud", "kind": "cloud" }
  ],
  "tabs": [
    {
      "diagrams": [
        {
          "nodes": [
            {
              "id": "api",
              "resourceRefsByProfile": {
                "local": ["api-process", "api-container", "api-logs", "api-requests"],
                "cloud": ["api-health-cloud", "api-logs-cloud", "api-requests-cloud"]
              }
            }
          ]
        }
      ]
    }
  ]
}
```

The architecture-map generator validates profile/resource IDs, makes bound nodes clickable and keyboard accessible, and embeds its localized inspector panel. Bind multiple resources to one node when its status, logs, and request history belong together. Keep bindings specific to each node and profile.

Run the generated HTML through `resource-inspector map --map ...`. A `file://` map remains static because browser requests cannot reach the local viewer.
